# fin-decision-matrix 投教网页改造规范（对标奶茶页）

> 基准页：`投教网页/每天省一杯奶茶，10 年后是多少？.html`（已验收，git 提交 fd273a5 / 5643594）
> 适用：`output/投教网页/*.html` 其余 29 页的视觉与结构对标改造。
> 品牌硬约束：全站使用 `assets/mangofolio-tokens-v09.css` 语义令牌 `var(--mf-*)`，禁止硬编码品牌色；芒果橙仅作点缀（≤5% 面积）；禁止死蓝/黑/暗色大面积铺底。

---

## 一、奶茶页改动要点（验收基线）

### 1. 整体配色（纯白底 + 暖墨正文 + 芒果橙点缀）
- 背景：纯白 `var(--mf-colors-background)`（#FFFFFF）
- 卡片面：`var(--mf-colors-background-surface)`（#FFFFFF）
- 暖灰分区底（结论框/表头/换算参考）：`var(--mf-colors-background-neutral)`（#F7F5F2）
- 正文墨：`var(--mf-colors-text)`（#3A332C）
- 深墨强调（h1/结论/加粗）：`var(--mf-colors-text-strong)`（#241610）
- 次级文字：`var(--mf-colors-text-weak)`（#8A7D70）
- 芒果橙强调（eyebrow/曲线/按钮/边线）：`var(--mf-colors-text-link)`（#F97316）
- 深橙（highlight 文字）：`var(--mf-colors-text-accent-mango)`（#E05E0A）
- 禁止再走原来的灰蒙风格（灰底灰字大面积弱对比）。

### 2. 结构骨架（自上而下）
```
eyebrow（英文栏目小标，芒果橙）
h1（页面主标题）
conclusion（一句核心结论，含动态数字），去掉标签，如：理性 + 如果当初。
hero（"先记住结论"引导块，左边 3px 芒果橙边线；只保留一处核心洞察，禁止重复）
legend + table（完整决策矩阵，首屏必须可见），不要标题。
section-title「为什么？」+ details.l2（讲给我听，解释计算逻辑）
chart-sub + chart-wrap svg（曲线图）
extra-note（换算参考）
section-title「底层假设（L3）」+ assume + foot
faq-title「常见问题（FAQ）」+ details.faq × N
cta（"用你自己的数字算一遍"）+ 算一算弹窗
footer（mangofolio 免责声明）
```

### 3. 表格矩阵（红涨绿跌，mangofolio 亮橙实色系）
- 表头：芒果橙浅底 `var(--mf-colors-primitives-mango-050)`，深墨字；行首列 `rowhead` 暖灰底左对齐。
- 档位色阶（金额越高越红=好、越低越绿=差，中国习惯红涨绿跌，正面意义是暖色系，负面反之）：
  - `--lvl1-bg: #B8221E`（≥30万 涨红）
  - `--lvl2-bg: #D4543E`（15-30万 橙红）
  - `--lvl3-bg: #F59E0B`（5-15万 琥珀，深字）
  - `--lvl4-bg: #1F8A4C`（1-5万 中绿）
  - `--lvl5-bg: #11693D`（<1万 跌绿）
- 单元格内容：`cell-amount` 终值 + `cell-note` 本金/利息（浅底档位用深字，如 lvl3）。
- 表格下方 legend 圆点图例，与色阶一一对应。
- 注意语义方向：数值越好/越高 → 红系；越差/越低 → 绿系，按每页业务含义换算，不可机械照搬。

### 4. 曲线图（SVG，芒果橙主色）
- 主曲线（终值/核心指标）：`var(--mf-colors-dataviz-mango-2)`（#F97316），线宽 3。
- 面积填充：同色 `fill-opacity: 0.28`。
- 对比线（本金/基准）：`var(--mf-colors-text-weak)` 灰色虚线（dash 2,5）。
- 网格线：`var(--mf-colors-dataviz-grid)`，坐标文字 `--mf-colors-text-weak`。
- 标注点/标注文字：mango-2 橙。
- 图例：灰虚线=基准，橙实线=主指标，置于图内底部。
- 每页按自身业务指标改写曲线（如：公积金页=总利息差、退休金页=累计领取额差）。

### 5. 删除项（对比 deepseek 旧版必须移除）
- statusbar（顶部灰色系统栏/状态条）→ 删除。
- 重复的核心洞察 → hero 内只保留一处"先记住结论"，正文/表格区不再重复同义大段结论。
- 「每月节省 × 坚持年限 → 终值」这类冗余小节标题 → 删除。

### 6. 动态一致性（静态文案与 JS 同源）
- 静态文案中的数字（结论、换算、FAQ）必须由 JS 同一计算函数渲染（`renderStatic` 模式：页面加载时用 `set('id', value)` 填 `<span class="dyn">`），禁止硬编码漂移；公式/参数改动时文案自动跟随。
- 每页保留原 `calcFutureValue` 等核心计算函数（同源），不得为省事写死数字。

### 7. 算一算弹窗（交互保留）
- 保留"算一算"交互弹窗（`.calc-modal` + overlay + dialog）：输入面板、实时重算、结果含本金/利息拆分与占比提示。
- 默认值取该页主场景参数；输入范围、步进按业务定。

### 8. SEO / Meta（保留原页）
- title/description/keywords、OG/Twitter、canonical、Article JSON-LD、FAQPage JSON-LD 均保留，只随页面主题更新。
- `assets/mangofolio-tokens-v09.css` 引用方式：`<link rel="stylesheet" href="assets/mangofolio-tokens-v09.css">`。

## 二、批量改造执行规范

1. **乱码修复先行**：被 PowerShell 写坏中文的 24 页（标题/正文乱码），必须从 `output/deepseek版本/同名.html` 提取原始中文内容修复，再套用本规范改造。所有文件最终 UTF-8（无 BOM）写入。
2. **逐页改造**：以奶茶页为模板，保留每页自身业务（题目、参数、计算逻辑、表格行列、FAQ 内容），仅对齐视觉与结构。
3. **首屏验收**：每页改完用浏览器/无头验证：首屏可见完整矩阵、无 statusbar、无重复洞察、曲线图为芒果橙。
4. **并排比对**：交付前将原版（deepseek版本）与转制版并排截图对比，确认未丢失业务内容。
5. **git 提交**：改造完成后提交到 fin-decision-matrix 仓库（连同 assets 目录、本规范文档）。
6. **数据一致性**：所有静态文案数字与 JS 计算一致（renderStatic 同源）。
