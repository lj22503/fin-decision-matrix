
# fin-decision-matrix 投教网页改造规范（对标 fintools 线上 guide 文章页）

> 基准页：fintools 线上版「4%法则多少钱才能财务自由？2026中国数据测算」
> 线上地址：https://fintools.mangofolio.com/guide/4-percent-rule.html
> 样式基准：线上 `guide.css`（视觉基准声明：投资词典词条详情页 —— 纯白底 / 白卡+1px 细线 / 暖墨正文 / 芒果橙点缀 / 16px 圆角）
> 适用：`output/投教网页/*.html` 全部 30 页（含奶茶页，一并回炉对齐）。
> 品牌硬约束：优先复用本地 `assets/mangofolio-tokens-v09.css` 语义令牌 `var(--mf-*)`；芒果橙仅作点缀（≤5% 面积）；禁止死蓝/黑/暗色大面积铺底；禁止大红大绿实色矩阵。

## 一、线上基准页结构（自上而下，逐块对照）

```
site-header（可选：品牌导航 + 面包屑，增强站点感）
paper 白纸卡（max-width 780px，居中，1px 细线 + 16px 圆角 + 弱阴影）
  paper-eyebrow（小字栏目标，芒果橙，letter-spacing 宽，左对齐）
  paper-title（衬线标题，深墨，下方 4-5px 橙色虚线装饰）
  lead-box（"结论先放这"：浅中性底 #F7F5F2 + 3px 橙左线 + 12px 圆角；只放核心结论）
  章节 × N（sec）：
    h2 章节标题（衬线，深墨，下方橙色虚线；如「一、4%法则是什么…」）
    正文段落 p（17px，行高 1.95，暖墨）
    ul/ol 列表（marker 为芒果橙）
    blockquote / formula-box（公式引用：浅底 + 3px 橙左线）
    tbl-wrap > table（朴素表格，见下方"表格规范"）
  cta-box（浅灰底 + 1px 细线 + 圆角 + 居中：标题/说明/橙底白字按钮）
  faq-sec（常见问题：details.faq-item 折叠，橙色小三角箭头）
  guide-related（相关推荐：白卡细线列表）
  guide-disclaimer（数据来源与免责声明，小字弱色）
```

## 二、配色 token（映射线上 guide 页基准值）

| 卡片面 | #FFFFFF | 白纸卡，1px 细线描边 |
| 中性弱底（结论框/表头/CTA） | #F7F5F2 | `var(--mf-colors-background-neutral)` |

## 三、表格规范（核心：去掉实色矩阵，回归朴素细线表）

- 结构：`.tbl-wrap`（横向可滚动）+ `caption`（表题，小字弱色，置表上方左对齐）+ `table`。
- 表头 `thead th`：中性浅灰底 `#F7F5F2`，深墨加粗字，左对齐，下 1px 细线。
- 内容行 `td`：白底，暖墨字，行间 1px 细线 `rgba(36,22,16,.06)`；末行无线。
- 数字列右对齐（`.num`）。
- **禁止**：红涨绿跌 lvl1-5 实色格子、色阶 legend、`border-spacing:3px` 彩色块。
- 关键数字强调：用 `<b>` 加粗或芒果橙文字（`.hl`），不铺色块。

## 四、删除项（相对旧版矩阵风格必须移除）

- 红涨绿跌实色矩阵 + 色阶 legend（lvl1-5、dot 图例）→ 改为朴素细线表格。
- hero 橙边大结论块 → 改为 `lead-box`（浅中性底 + 3px 橙左线，同一内容）。
- 居中英文 eyebrow → 改为左对齐小字栏目标（paper-eyebrow 风格）。
- statusbar / 重复的核心洞察 → 删除，结论只在 lead-box 出现一次。
- SVG 大曲线图（chart-wrap）→ 若业务强相关可保留为简单橙线图，否则删除；禁止橙色大面积面积填充。
- 「底层假设（L3）」大段折叠 → 并入正文小节「测算假设」普通段落或 details，视觉收敛。

## 五、保留项（业务与交互不丢）

- 每页自身业务内容：题目、参数、计算逻辑、表格行列、FAQ 问题与答案、免责声明。
- 「算一算」交互弹窗：保留，视觉对齐 guide 风（白卡 + 1px 细线 + 橙底白字按钮 + 浅灰结果面板）。
- renderStatic 同源渲染：静态文案数字由 JS 同一计算函数填充，禁止硬编码漂移。
- SEO/Meta：title/description/keywords、OG/Twitter、canonical、Article JSON-LD、FAQPage JSON-LD 保留。

## 六、字体与排版

- 正文：sans 栈（复用 `--mf-fonts-sans`），17px，行高 1.9~1.95，letter-spacing .01em。
- 标题：衬线栈（`--mf-fonts-display`，近似 Noto Serif SC），h1 clamp(1.6~2.2rem)，h2 clamp(1.25~1.45rem)。
- 阅读宽度：主内容 max-width 780px 居中；卡片圆角 16px、次级 12px。
- 移动端（≤640px）：正文 16px、标题降档、表内 padding 收紧。

## 七、批量改造执行规范

1. 逐页改造：以线上 4% 法则页结构为模板，保留每页自身业务（题目/参数/计算/FAQ/弹窗），仅对齐视觉与结构。
2. 乱码修复先行：被 PowerShell 写坏中文的页，先从 `output/deepseek版本/同名.html` 提取原始中文修复，再套用本规范。
3. 首屏验收：首屏看到"白纸卡 + 标题虚线 + lead-box 结论 + 朴素表格"，无实色矩阵、无 statusbar、无重复洞察。
4. 样板先行：先改 1 页（多笔债务页）经用户确认，再批量其余 29 页。
5. git 提交：改造完成后提交到 fin-decision-matrix 仓库。
