# 二维决策矩阵

一行一列交叉，查表即得答案。把复杂的、多变量的决策，压缩成"输入变量 A × 输入变量 B → 输出决策结论"的查表过程。

## 核心定义

- **两个关键输入变量**：用户做决策时主要权衡的两个维度（如：我有多少钱 vs 我每年花多少钱）
- **一个明确输出**：年份、金额、等级、明确的"是/否"行动建议
- **使命**：化繁为简，消除焦虑。把思考过程前置并固化在设计中，用户只需对号入座

## 适用判断（检查清单）

做之前逐条过，全部满足才做：

1. 存在两个关键输入变量，用户需要在它们之间权衡
2. 输出结论明确且可量化（年限 / 金额 / 等级 / 是/否）
3. 存在公认的数学模型或经验公式（复利公式、增长模型、概率公式等）
4. 决策有实际意义，用户真的需要根据它做选择
5. 涉及复利、乘法、杠杆、概率复合、临界点等非线性关系——这是矩阵图的甜区，人们单看数字感知不到

**不适用**：多因素综合评分（3 个以上变量）、纯时间序列、单一变量简单计算、无公认公式的主观判断。

## 结构规范

一张标准矩阵图必须包含：

- **标题**：明确主题，如"躺平需要多少钱"
- **列（横轴）**：初始资金 / 变量 A 梯度（100万、200万、300万、500万…）
- **行（纵轴）**：年度花费 / 变量 B 梯度，每行标注具体数值（不要只写"每年"）
- **单元格**：两个变量交叉的计算结果——可持续年限 / 总金额 / 等级 / 行动建议
- **永续/上限标注**：超过阈值显示"花不完""永续"等，而不是空着
- **假设条件说明**：年化收益率、通胀率、提取规则、模型类型，必须写清楚
- **颜色编码**：红（快速耗尽 / 危险）→ 黄（中等）→ 绿（永续 / 安全）
- **脚注**：免责与假设边界

## 核心计算模型

按场景选择，并在图中注明用了哪一个：

1. **简单除法模型**（无回报）：年限 = 本金 ÷ 年度花费
2. **固定回报率模型**（年金公式）：

```
年化收益率 r、本金 P、年花费 W：
若 W ≤ P × r → 永续（花不完）
否则 n = log(1 + r·P/W) / log(1 + r)
```

3. **安全提取率模型**（4% 规则）：年度花费 ≤ 本金 4% 视为大概率永续
4. **概率模型**（蒙特卡洛）：单元格给"成功概率"而非确定数字，如"95% 概率可持续 30 年以上"
5. **负债场景**：
   - 等额本息还清月数：`n = -ln(1 - P·r/月供) / ln(1 + r)`，月供 ≤ 月利息时永不还清
   - 信用卡最低还款：余额 × 最低比例 vs 月利息，还款额 ≤ 利息 → 永不还清
   - 雪崩法（先还高利率）/ 雪球法（先还小余额）：多笔债务总月数 + 总利息对比

## 设计原则

- **让核心假设成为第三维度**：关键假设（如收益率）做多版本并列，或做成滑块，用户瞬间看到结论对假设的敏感度
- **替换绝对结论为概率与风险**："花不完"改为">50 年（高概率永续）"，更专业的用成功概率
- **增加关键警示注解**：在显著位置注明"本表基于 4% 实际收益率（已扣除通胀）；历史表现不代表未来"
- **临界线标注**：画出成功/失败分界线，直观显示需要跨越的阈值
- **防误导**：透明简化——假设必须显式，不把不确定性藏起来

## Gotchas

- 矩阵图是"思考起点"不是"思考终点"——它框定问题、促进讨论，但最终决策必须建立在对背后逻辑的理解上
- 不要隐藏关键假设。收益率、通胀率这些"看不见的变量"往往是结论的基石
- 行标签必须给具体数值，不能只写"每年"——否则表格不可查
- 单元格显示要统一口径：要么都用年限，要么都用金额，不要混
- 纯表格/SVG 页交互可以 100% 保留计算逻辑，只重构外观
- 颜色语义要符合直觉：红=危险/耗尽，绿=安全/永续，黄=中间
- 若结果对假设极度敏感（收益率降 1% 就从"花不完"跌到"只能撑 20 年"），必须在图中突出这个敏感度

## 生成器工作流

三类用户场景：小白模板（预制模板填空）、专业配置（自定义行列/公式/显示）、开发者 API（集成到 SaaS）。

工具功能闭环：选模板 → 配参数（行列序列、公式、假设、阈值、配色）→ 计算填充 → 可视化（表格/热力图/临界线）→ 导出（PNG/SVG/PDF/嵌入代码）→ 分享。

MVP 路线：先做透 1-2 个高频场景（退休规划、负债还款），再抽象通用化。
